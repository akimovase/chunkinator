# chunkinator

Разбиение `pandas.DataFrame` по одной колонке на чанки желаемого размера так, что
одинаковые значения никогда не оказываются в разных чанках.

## Задача

- каждый чанк содержит **не меньше** `chunk_size` строк, кроме, возможно, последнего (хвоста);
- строки с одинаковым значением колонки всегда попадают в один чанк — это условие важнее
  размера, поэтому чанк может быть больше `chunk_size`;
- решение должно экономно расходовать память.

Чанки нарезаются жадно: берём `chunk_size` строк и расширяем чанк до конца группы, в которую
попала последняя из них. Для серии `1, 1, 2, 2, 2, 3`:

| `chunk_size` | чанки |
|---|---|
| 1–2 | `[1, 1]` `[2, 2, 2]` `[3]` |
| 3–5 | `[1, 1, 2, 2, 2]` `[3]` |
| ≥ 6 | `[1, 1, 2, 2, 2, 3]` |

## Использование

```python
import pandas as pd
from chunkinator import iter_chunks, iter_grouped_chunks

dfs = pd.date_range("2023-01-01 00:00:01", "2023-01-01 00:00:04", freq="s")
df = pd.DataFrame({"dt": dfs.repeat(3)})

for chunk in iter_chunks(df, "dt", chunk_size=4):
    print(len(chunk))  # 6, 6

for chunk in iter_grouped_chunks(df, "dt", chunk_size=4):
    print(len(chunk))  # 6, 6
```

- `iter_chunks(df, column, chunk_size, *, sort=False)` — ленивый генератор чанков-срезов `df`.
  Аргументы проверяются сразу при вызове, а не при первой итерации.
  Если колонка не отсортирована по возрастанию, поднимается `ValueError`; с `sort=True`
  фрейм один раз стабильно сортируется (одна копия) и режется уже он.
  Пропуски (`NaN`/`NaT`) в колонке дают `ValueError`.
- `iter_grouped_chunks(df, column, chunk_size)` — те же правила размера, но группы собираются в
  чанки непоследовательно, чтобы чанки были как можно ближе к `chunk_size`.


## Алгоритм для отсортированной колонки: `iter_chunks`

У нас есть n — строк, G — групп одинаковых значений, K — чанков:

- Время O(n + K log n) 
- Память O(1)

Отсортированная колонка — это уже готовый индекс для бинарного поиска, поэтому
конец очередного чанка находится одним вызовом:

```python
end = np.searchsorted(values, values[start + chunk_size - 1], side="right")
```

- `df[column].to_numpy()` для `datetime64` — view без копирования;
- вспомогательных массивов размера n нет; O(n) остаётся только проверка `is_monotonic_increasing`;
- каждый чанк — `df.iloc[start:end]` по непрерывному диапазону, т.е. срез без копирования данных;
- результат — генератор, так что чанки не накапливаются в памяти.


## Алгоритм для оптимальной раскладки: `iter_grouped_chunks`

Отдельная функция с теми же правилами, что и у `iter_chunks`, но без требования, чтобы чанк был
непрерывным отрезком колонки:

- каждый чанк, кроме последнего, содержит **не меньше** `chunk_size` строк;
- группа одинаковых значений не разрывается;
- группа из `chunk_size` строк или больше — отдельный чанк: добавлять к ней что-то бессмысленно;
- меньшие группы собираются вместе так, чтобы чанки как можно меньше превышали `chunk_size`.

```python
from chunkinator import iter_grouped_chunks

# секунды 1–4, каждая по 3 строки; chunk_size=4
[len(c) for c in iter_grouped_chunks(df, "dt", 4)]  # [6, 6]

# группы 4, 2, 1, 3, 5, 6 строк; chunk_size=7
# iter_chunks:        7 + 8 + 6
# iter_grouped_chunks: (6+1) + (5+2) + (4+3) = 7 + 7 + 7
```

**Алгоритм.** Мы пытаемся получить как можно больше полных чанков. Чанк начинается с самой
большой из оставшихся групп. Пока он меньше `chunk_size`, в него добавляется самая маленькая
группа, которая закрывает недостачу, а если такой нет — самая большая из оставшихся. Недобрать
может только самый последний чанк, когда группы закончились, "хвостовой" чанк выдаётся последним. Остальные
чанки упорядочены по наименьшему значению, строки внутри чанка идут в исходном порядке.
Колонка в изначальном датафреме может быть не отсортирована.

- **Временные интервалы чанков могут пересекаться** (в примере 7+7+7 чанки покрывают секунды
  1 и 4, 2 и 5, 3 и 6). 

- Время O(n log n): сортировка n строк по номеру чанка
- Память O(n), тк в отличии от iter_chunks для описания чанка недостаточно только границ

## Разработка

Основные команды собраны в `Makefile` (`make` без аргументов показывает список):

| Команда | Что делает |
|---|---|
| `make install` | создаёт `.venv`, ставит пакет с dev-зависимостями и pre-commit хук |
| `make lint` | проверяет стиль: линтер и форматтер ruff |
| `make format` | исправляет стиль автоматически |
| `make typecheck` | проверяет типы: mypy в строгом режиме |
| `make test` | запускает тесты |
| `make cov` | тесты с покрытием (порог 95%) |
| `make check` | всё, что запускает CI: `lint`, `typecheck`, `cov` |
| `make run` | запускает демо `main.py` |
| `make clean` | удаляет кэши и файлы покрытия |

Pre-commit хук (`.pre-commit-config.yaml`) запускает `make check` перед каждым коммитом и не даёт
закоммитить код, который не прошёл бы CI. Непроиндексированные изменения на время проверки
откладываются, так что проверяется ровно то, что попадёт в коммит.

Тесты: примеры из задания, граничные случаи (пустой фрейм, одна строка, группа больше
`chunk_size`, все значения уникальны, неотсортированный вход, пропуски,
некорректные аргументы), проверка, что чанки не копируют данные, и property-based тест на
`hypothesis`, который проверяет инварианты на случайных данных: покрытие без пропусков,
группы не разрываются, размер ≥ `chunk_size`, минимальность каждого чанка.

CI (GitHub Actions, `.github/workflows/ci.yml`): линтер и форматтер ruff, mypy `--strict`,
pytest с покрытием на Python 3.11–3.14.
